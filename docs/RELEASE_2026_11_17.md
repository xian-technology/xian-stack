### Second failure: nested Make corrupts backend JSON

The user subsequently reported v0.3.5 failed. Inspection of run 44202339923
confirmed the policy-default fix worked: full E2E passed bootstrap through
`20-quorum-recovery`, including throughput and BDS recovery checks. It then
failed `21-fresh-node-sync` during public CLI `snapshot export`:
`xian-stack backend command failed (status): Expecting value: line 1 column 1`.
Image publication, the GitHub image release and reproducibility were skipped.

The gate invokes `make localnet-e2e`, which exports `MAKELEVEL` to its Python
children. Snapshot export queries the backend's status, which invokes Make
again and parses stdout as JSON. GNU Make 4 automatically prints entering/
leaving-directory banners for this nested invocation, corrupting the status
JSON. A network-free container reproduction confirmed the GNU Make 4 behavior;
macOS's GNU Make 3.81 needs the inherited `w` flag to reproduce the banners.

The backend now passes `--no-print-directory` for its Make calls. This keeps
the machine-readable output contract for status and storage reporting, while
preserving command errors and their diagnostics. Real-Make regression cases
cover both inherited flag settings, plus failure propagation. The banner case
failed before the fix; the fixed backend also produced valid JSON under GNU
Make 4 in an isolated, network-free container with no live state mounted.

Focused validation: 16 tests and two subtests passed; all four changed-function

## Leave-announcement recovery: 2026-11-19

The user reported v0.3.7 run 44440254467 failed. Full E2E passed, and protocol
stages 00–07 passed, including the corrected payout check, hybrid membership
and real duplicate-vote evidence. The last stage, `08-leave-announcement`,
expected rebalance to evict an announced validator. The chain instead retained
the active validator with status `leaving` and a seven-day deadline. Publishing
was skipped. Evidence is artifact 14494087408, under
`public-localnet-protocol/20261119T024948Z/`; local copies are in
`/tmp/xian-image-v037-artifacts` and `/tmp/xian-image-v037-failed.log`.

Premise audit before another fix: the harness assigns itself authority over
financial and membership outcomes that belong to committed protocol rules.
There are two actors defining these expectations: the released VM/contracts
and the runner. The fee-blind payout check and immediate removal expectation
are two instances of that split. Remove the runner's independent assignment:
check actual receipt charges for payouts and committed active membership
through the notice period, while retaining enforcement of early-leave denial.

The frozen validators contract explicitly keeps an already-active announcing
validator selectable; only a successful `leave()` completes its exit. Its
existing native regression tests retention after announcement and removal
after the full delay. The live runner already checks early `leave()` fails,
so its immediate-eviction/standby expectations contradict that rule. The
replacement must preserve the positive seven-day delay and original runtime
pins, verify retained membership/deadline, and correct the stale coverage notes.

The runner now derives expected notice-period membership from the committed
pre-announcement set, requires the announcing validator to remain active, and
checks its deadline is unchanged. Early-leave rejection, the seven-day delay,
live validator count and real runtime rules are unchanged. Standby promotion
remains covered by the evidence-removal phase, not the notice phase. The local
protocol documentation and generated coverage notes now describe that split.
Published operator docs already describe announcement followed by delayed
`leave()` correctly, so no public workflow change is needed.

All four new phase regressions failed before the fix. They now pass, including
rejection of premature eviction, an inactive record and a changed deadline.
The focused suite passed 31 tests; main's full local suite passed 1423 tests,
